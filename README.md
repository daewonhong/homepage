# 홍대원 AI 리터러시 홈페이지

별도 설치·빌드 없이 사용할 수 있는 HTML·CSS·JavaScript 홈페이지입니다.

## 1. 먼저 확인하기

가. ZIP 압축을 해제하고 `index.html`을 브라우저로 여세요. ZIP 미리보기에서 바로 열지 마세요.
나. `index.html`, `style.css`, `script.js`, `assets` 폴더의 위치를 유지하세요.
다. 강사 사진과 그림책 2장은 원본 파일 그대로 포함되어 있습니다.
라. 그림책은 별개의 작업 사례로 표시했습니다. 출간 완료·판매 실적을 의미하지 않습니다.

## 2. 파일 구성

| 파일 | 수정할 내용 |
| --- | --- |
| index.html | 소개 문구, 프로그램, 작품 설명, FAQ, 페이지 제목 |
| style.css | 색상, 글자 크기, 여백, 반응형 배치 |
| script.js | 대상별 안내, 문의 설정, 이미지 확대, 메뉴 기능 |
| assets/profile-hong.png | 홍대원 프로필 사진 |
| assets/picturebook-spread.png | 그림책 펼침면 |
| assets/picturebook-cover.png | 그림책 표지 |
| .nojekyll | 정적 파일 배포용 빈 설정 파일 |

## 3. 문의 연락처 연결

가. `script.js` 상단의 `SITE_CONFIG`를 수정하세요. 공개할 연락처만 입력합니다.

```js
const SITE_CONFIG = {
  email: '',
  phone: '',
  inquiryFormUrl: '',
  podcastUrl: '',
  blogUrl: ''
};
```

나. 이메일은 email, 전화번호는 phone의 따옴표 안에 넣으세요. 비워 두면 해당 연락처가 표시되지 않습니다.
다. 외부 문의 폼·팟캐스트·블로그 주소는 `https://`로 시작하는 전체 주소를 넣으세요.
라. 현재 문의 폼은 입력값 검증 → 문의 내용 정리 → 복사까지 작동합니다. 문의 내용을 서버에 저장하거나 자동 전송하지 않습니다.
마. email을 입력하면 정리된 내용을 담아 이메일 앱을 여는 버튼이 나타납니다. 사용자가 이메일 앱에서 직접 보내야 합니다. 기기의 기본 메일 앱 설정에 따라 열리지 않을 수 있습니다.
바. inquiryFormUrl을 입력하면 외부 문의 폼 열기 버튼이 나타납니다. 정리한 내용을 복사한 뒤 외부 폼에서 직접 작성·제출합니다. 외부 폼에 자동 입력되지는 않습니다.
사. 실제 개인정보 수집을 외부 폼으로 연결할 경우 해당 폼에 수집 목적·항목·보유기간·동의 안내를 설정하세요. 현재 사이트는 문의 내용을 브라우저 저장소에 보관하지 않습니다.
아. 연락처 연결 전 공개하면 방문자는 내용을 복사할 수 있지만 전달할 곳이 없습니다. 공개 전에 이메일 또는 문의 폼을 연결해 주세요.

## 4. GitHub Pages에 공개하기

가. GitHub에 로그인하고 오른쪽 위 `+ → New repository`를 선택합니다.
나. 저장소 이름을 `실제깃허브아이디.github.io`로 입력합니다. 이미 같은 이름의 저장소가 있다면 새로 만들지 말고 기존 파일을 먼저 확인하세요.
다. 무료 계정은 `Public`을 선택합니다. `Add a README file`을 선택하고 저장소를 만듭니다.
라. 저장소 `Code` 화면에서 `Add file → Upload files`를 선택합니다.
마. ZIP이 아닌, 압축을 푼 폴더 안의 파일과 `assets` 폴더를 업로드하고 `Commit changes`를 누릅니다. `index.html`이 저장소 첫 화면에 보여야 합니다. `.nojekyll`은 파일 선택기의 숨김 파일 설정에 따라 보이지 않을 수 있으며, 이 홈페이지는 해당 파일 없이도 일반 HTML로 배포할 수 있습니다.
바. `Settings → Pages`로 이동합니다.
사. `Source: Deploy from a branch`, `Branch: main`, `폴더: /(root)`를 선택하고 `Save`를 누릅니다.
아. 배포 상태는 `Actions`, 공개 주소는 `Settings → Pages`에서 확인합니다. 완료 후 `Visit site`를 누릅니다.
자. 사용자 사이트 주소는 `https://실제깃허브아이디.github.io/`입니다. 다른 이름의 저장소를 사용하면 보통 그 주소 뒤에 `/저장소이름/`이 붙습니다. 파일들은 상대경로이므로 두 방식 모두 대응합니다.
차. 공개 후 휴대폰에서 프로필 사진·그림책·문의 연결을 다시 확인하세요.
카. 수정 시 같은 경로에 수정 파일을 다시 업로드하고 `Commit changes`를 누르면 재배포됩니다.
타. 배포가 실패하면 `Actions`에서 실패 항목을 확인하고 `index.html` 위치, main 브랜치, Pages 설정을 확인하세요.

공식 안내:
- https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site
- https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## 5. 검색·공유 설정

가. 기본 제목, 설명, Open Graph 제목·설명·이미지, 파비콘을 설정했습니다.
나. 공개 주소가 확정되면 `index.html`의 `og:image`를 실제 전체 이미지 URL로 바꾸세요. 예: 사이트 주소 뒤에 `assets/profile-hong.png`를 붙인 주소입니다. 상대경로 이미지의 공유 미리보기 지원은 플랫폼마다 다릅니다.
다. 공개 주소가 정해진 뒤 canonical과 og:url을 추가할 수 있습니다. 현재는 임의의 공개 주소를 넣지 않았습니다.
라. 검색 노출과 메신저 공유 미리보기는 실제 공개 후 해당 서비스에서 확인해야 합니다.

## 6. 검수 결과와 남은 작업

가. 확인한 항목
1) 데스크톱 1363px 화면의 첫 화면과 한글 표시, 가로 넘침 없음
2) 390px 프레임(내부 가용 폭 375px)의 모바일 배치와 메뉴, 가로 넘침 없음
3) 프로필 사진과 그림책 이미지 로딩 및 그림책 원본 비율 유지
4) 교육 대상 버튼 선택 시 안내 내용 전환
5) 그림책 이미지 확대, 닫기, Escape 닫기와 초점 복귀
6) 그림책 문의 클릭 시 책 만들기 프로그램 자동 선택
7) 필수 입력·잘못된 연락처 검증과 문의 내용 정리
8) JavaScript 구문 검사와 로컬 파일 경로 검사

나. 아직 연결하지 않은 항목
1) 이메일·전화번호·외부 문의 폼
2) 팟캐스트·블로그 링크
3) GitHub 공개 배포와 공개 주소

다. 검수 한계
1) 실제 스마트폰 기기와 모든 브라우저 조합의 검수는 진행하지 않았습니다.
2) 클립보드 기능은 브라우저 권한과 HTTPS 여부에 따라 다릅니다. 자동 복사가 불가능하면 내용을 선택해 수동 복사하도록 안내합니다.
3) 실제 이메일 발송, 외부 폼 제출, GitHub 배포와 검색·공유 미리보기는 연결·공개 후 확인해야 합니다.
4) 현재 미연결 상태이므로 개인정보를 외부로 보내지 않습니다. 추후 외부 서비스를 연결하면 그 서비스의 처리 방침도 확인해야 합니다.

## 7. 이미지·저작 표기

가. 강사 사진과 그림책 이미지는 제공된 파일을 복사했습니다. 얼굴 보정과 그림 변경은 하지 않았습니다.
나. 표지의 `글 홍대원 · 원화 이정숙` 표기를 유지했습니다.
다. 본문의 `똑같은 노랑?`은 장면 제목으로만 표시합니다.
라. 두 이미지를 같은 책의 표지와 본문으로 연결하거나 수강생 성과로 표시하지 않았습니다.
